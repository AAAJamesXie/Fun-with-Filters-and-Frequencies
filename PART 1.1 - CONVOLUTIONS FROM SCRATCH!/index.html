01 / A selfie through three filters

The original JPEG is 1279 × 1706 pixels. Pillow converts it to grayscale, resizes it proportionally to 480 × 640 with Lanczos resampling, and NumPy represents it as float64 in [0, 1]. Every convolution uses this same input. Pillow is used only for image I/O and preparation; both handwritten convolution algorithms use NumPy alone.

Box = ones((9, 9)) / 81   ·   Dx = [1, −1]   ·   Dy = [1, −1]T

The box filter averages 81 samples, softening the hair, glasses and jacket detail. Dx measures left-to-right intensity changes and emphasizes vertical boundaries; Dy measures top-to-bottom changes and emphasizes horizontal boundaries. With convolution and these kernels, interior derivatives are I[y, x] − I[y, x−1] and I[y, x] − I[y−1, x].

Derivative arrays retain their signed values. For display only, zero becomes middle gray, positive changes become brighter, and negative changes darker. Both directions use the same scale, ±0.960784; they are not independently normalized or clipped to positive values.

02 / Convolution, written by hand

Convolution flips the kernel along both axes before the multiply-and-sum operation. Omitting this flip would implement correlation, which changes the sign or orientation of asymmetric filters.

Both versions have O(HWkhkw) arithmetic cost. Four loops visit every output pixel and every kernel coefficient in Python. Two loops still visit every output pixel, but NumPy handles the kernel-sized multiplication and sum. No built-in convolution, FFT, stride trick or high-level filtering function is used inside either implementation.

Shared zero padding and kernel flip

def prepare(image, kernel):
    """Float64 avoids unsigned subtraction; padding matches SciPy 'same'."""
    image = np.asarray(image, dtype=np.float64)
    kernel = np.asarray(kernel, dtype=np.float64)
    if image.ndim != 2 or kernel.ndim != 2 or not image.size or not kernel.size:
        raise ValueError('Image and kernel must be nonempty 2D arrays.')
    if not np.isfinite(image).all() or not np.isfinite(kernel).all():
        raise ValueError('Image and kernel must contain finite values.')
    kh, kw = kernel.shape
    # Even kernels need one more zero before than after the image.
    padded = np.pad(image, ((kh // 2, (kh - 1) // 2),
                            (kw // 2, (kw - 1) // 2)), mode='constant')
    flipped = kernel[::-1, ::-1]
    return image, padded, flipped

Four-loop implementation

def convolve_four_loops(image, kernel):
    """Two loops over output pixels and two over kernel coefficients."""
    image, padded, flipped = prepare(image, kernel)
    height, width = image.shape
    kh, kw = flipped.shape
    result = np.zeros((height, width), dtype=np.float64)
    for y in range(height):
        for x in range(width):
            for ky in range(kh):
                for kx in range(kw):
                    result[y, x] += padded[y + ky, x + kx] * flipped[ky, kx]
    return result

Two-loop implementation

def convolve_two_loops(image, kernel):
    """Two loops over output pixels; NumPy multiplies and sums each patch."""
    image, padded, flipped = prepare(image, kernel)
    height, width = image.shape
    kh, kw = flipped.shape
    result = np.zeros((height, width), dtype=np.float64)
    for y in range(height):
        for x in range(width):
            result[y, x] = np.sum(padded[y:y + kh, x:x + kw] * flipped)
    return result

Boundary handling

Values outside the image are zero; the output has the same dimensions as the input. A 9 × 9 kernel receives four zeros on each side. A 1 × 2 kernel receives one zero on the left and none on the right; a 2 × 1 kernel receives one above and none below. This asymmetric padding matches SciPy's centering convention for even kernels.

Zero padding darkens the outer rim of the box-filter image because some of its 81 samples are zero. It also creates artificial differences against zero at the left boundary for Dx and the top boundary for Dy. These are boundary effects, not scene edges; reflection or edge replication would produce different results.

What I learned

A correct convolution depends on both the kernel flip and its boundary convention. Vectorizing the inner calculation reduces Python overhead without changing the mathematics, but for very small kernels that overhead tradeoff can reverse. Signed derivatives also need a different display mapping from ordinary photographs.
